Les 5 urgences

3 critiques · 2 fortes

Les points qui coûtent le plus cher aujourd'hui — chacun se corrige en quelques heures, sauf le premier (une à deux journées).

U1 ✓ Fait — 02/09/2026 Critique Effort M Performance

Tout le site est rendu dynamiquement à cause d'un seul appel headers() dans la page 404

La lecture de x-pathname dans not-found.tsx désactive le prérendu de toutes les routes : le build ne produit aucune page statique, l'ISR quotidien déclaré dans le layout est inopérant, et chaque visite déclenche un rendu React complet côté serveur (la home : 599 Ko de HTML générés à chaud, aucune mise en cache CDN possible). Vérifié expérimentalement : en neutralisant ce seul appel, tout le site repasse en statique avec revalidation 24 h.

Proposition : rendre la 404 localisée depuis [...rest]/page.tsx (qui reçoit la locale en paramètre), ou lire la locale côté client dans le boundary — puis vérifier que le build affiche bien « SSG » sur toutes les routes.

✓ Réalisé : appel headers() supprimé — la 404 dérive désormais la locale de l'URL côté client (NotFoundContent.tsx). Build vérifié : 583 pages prérendues en statique (SSG), seuls le catch-all 404 et l'API contact restent dynamiques.

src/app/[lang]/not-found.tsx · src/components/layout/NotFoundContent.tsx

U2 Critique Effort S Conversion

Aucun outil de mesure : le taux de conversion est impossible à piloter

Toute la plomberie existe (Consent Mode v2 initialisé, bannière opt-in conforme CNPD) mais aucun tag analytics n'est chargé — on demande un consentement cookies pour des traceurs qui n'existent pas. La page /merci, objectif de conversion parfait, n'est trackée par rien. Pour une agence qui vend « la conversion mesurable d'abord », c'est aussi une incohérence commerciale.

Proposition : brancher GA4 (le câblage est prêt, ~1 h) ou un outil sans cookie (Plausible/Umami), avec 4 événements : étape du formulaire, soumission, ouverture du chat, arrivée sur /merci. Prérequis de presque toutes les autres propositions business.

src/components/layout/ConsentScript.tsx · src/app/[lang]/merci/page.tsx

U3 ✓ Fait — 02/09/2026 Critique Effort S Accessibilité

L'indicateur de focus clavier est quasi invisible en thème clair (ratio 1,23:1)

Le contour de focus utilise le lime brut #c8f02e, jamais remappé en thème clair : sur fond clair le ratio tombe à 1,23:1 (minimum requis : 3:1). Le thème clair étant appliqué site-wide, toute la navigation clavier du site est concernée — y compris, ironiquement, les modes « focus renforcé » et « contraste élevé » du widget d'accessibilité.

Proposition : une règle CSS — html:not(.dark) :focus-visible { outline-color: var(--accent-strong) } (4,78:1) — appliquée aussi aux modes du widget.

✓ Réalisé : les trois règles :focus-visible (base, mode « focus renforcé », mode « contraste élevé ») pointent sur --accent-strong : olive 4,78:1 en thème clair, lime inchangé en thème sombre, ≥ 3:1 aussi sur les sections « stage » sombres.

src/app/globals.css

U4 ✓ Fait — 02/09/2026 Fort Effort S Sécurité

npm audit (exécuté réellement) remonte notamment : HTTP request smuggling via rewrites, contournement du proxy par les routes de prefetch — directement pertinent puisque tout le routage de langue repose sur src/proxy.ts —, cache poisoning des réponses RSC et DoS de l'API d'optimisation d'images.

Proposition : monter next en 16.3.1 (corrige aussi sharp et postcss embarqués), puis npm audit fix pour les chaînes dev.

✓ Réalisé : next et eslint-config-next montés en 16.3.4, npm audit fix exécuté, puppeteer-core monté en 25.9.0 (chaîne dev) : npm audit = 0 vulnérabilité. Build de production vérifié.

U5 Fort Effort S Légal · Conversion

Les pages légales affichent « [À COMPLÉTER] » et un bandeau « à faire valider juridiquement »

Mentions légales, confidentialité et cookies sortent en production avec le bandeau « ⚠️ Contenu à faire valider… », « Dernière mise à jour : à compléter », et des placeholders visibles : directeur de la publication, hébergeur (mention obligatoire — loi luxembourgeoise du 14 août 2000), durées de conservation, liste des outils. Or la dernière étape du formulaire de contact oblige à cocher une case qui lie vers /confidentialite : le prospect atterrit, au moment décisif, sur une page qui s'auto-déclare non valide.

Proposition : compléter site.legal (hébergeur, directeur, durées, sous-traitants réels : hébergeur + Resend), dater, puis retirer le bandeau. Coût quasi nul, crédibilité immédiate au point le plus sensible du tunnel.
